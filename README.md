# Auto Assignment для JIRA

Плагин автоматически заполняет поля задачи при её создании по настраиваемым правилам.

Заполняемые поля:

- **Исполнитель** (стандартное поле `assignee`);
- **Соисполнитель** (настраиваемое пользовательское поле типа «Выбор пользователя»);
- **Наблюдатели** (стандартный список watchers).

Правило срабатывает, если задача создана в проекте, для которого оно задано, и все условия правила совпали с полями задачи.

> Правило всегда привязано к проекту: проект — неявный элемент правила. В списке полей условий его нет, потому что страница настроек открывается в контексте конкретного проекта.

---

## Сборка и установка

```bash
mvn package
```

Артефакт: `target/autoassignment-0.1.15.jar`. Устанавливается через **Управление приложениями → Upload app** (или в `jira-home/plugins/installed-plugins`). Для применения изменений в Java-коде нужен перезапуск JIRA.

Требования: JIRA Server/Data Center **8.20.x**, Java 11.

---

## Глобальные настройки (администратор JIRA)

Открываются из меню администрирования: **Administration → Add-ons → Auto Assignment** (или напрямую `/plugins/servlet/autoassignment/global-config`).

Доступно только глобальному администратору JIRA. Настройки:

| Настройка | Описание |
|---|---|
| **Включить автоматическое назначение** | Глобальный выключатель. Если выключен, ни одно правило не применяется. |
| **Поле «Соисполнитель»** | Пользовательское поле типа «Выбор пользователя» (single или multi user picker), в которое записываются соисполнители. Без выбранного поля правила, задающие соисполнителей, игнорируют это поле. |

## Правила проекта

Открываются из **Настройки проекта → Auto Assignment** (левая панель). Доступно администратору проекта.

Страница содержит таблицу правил и кнопку **«Добавить правило»**, открывающую модальное окно.

### Структура правила

| Поле | Описание |
|---|---|
| **Название** | Произвольное имя правила (обязательно). |
| **Исполнитель** | Один пользователь (необязательно). |
| **Соисполнители** | Один или несколько пользователей (необязательно). |
| **Наблюдатели** | Один или несколько пользователей (необязательно). |
| **Условия** | Набор условий; правило срабатывает, если выполнены **все** условия. Пустой набор = правило применяется всегда. |
| **Активно** | Выключенное правило не применяется. |

В одном правиле можно заполнить любую комбинацию целевых полей — например, сразу исполнителя и наблюдателей.

### Порядок применения

Правила применяются по порядку (по возрастанию `SORT_ORDER`). Для каждого целевого поля берётся **первое подходящее** правило, у которого это поле задано. То есть разные правила могут задавать разные поля (одно — исполнителя, другое — наблюдателей).

## Условия и операторы

Каждое условие состоит из **поля**, **оператора** и **значения (значений)**.

| Оператор | Семантика |
|---|---|
| **равно** | Фактическое значение поля совпадает с **любым** из выбранных значений. |
| **не равно** | Фактическое значение не совпадает **ни с одним** из выбранных. |
| **содержит** | Фактическое значение содержит **любое** из выбранных (без учёта регистра). |
| **пусто** | Поле не заполнено. Значение не требуется. |
| **не пусто** | Поле заполнено. Значение не требуется. |

Если для операторов `равно`/`не равно`/`содержит` значения не выбраны, условие считается невыполнимым (`равно`/`содержит`) либо тривиально выполненным (`не равно`).

### Мультивыбор значений

Для полей с предопределённым набором значений (пользователи, типы задач, приоритеты, опции и т.д.) значение выбирается **мультиселектом** (AUI Select2 с поиском). Можно отметить несколько значений — условие сработает по принципу «любое из».

## Настройка условий для разных типов полей

### Пользователи (user picker)

Поля типа «Выбор пользователя» (как системные `Исполнитель`, `Автор`, так и кастомные user picker) показывают **список пользователей** с поиском. Можно выбрать несколько.

Пример: *Исполнитель **равно** [Иванов, Петров]* — сработает, если исполнитель задачи Иванов или Петров.

### Опции (select / radio / checkbox)

Поля с фиксированным списком опций («Список», «Переключатели», «Флажки», множественный выбор) показывают **список опций** этого поля — выбирайте нужные значения мультиселектом.

Пример: *Кастомное поле «Команда» **равно** [Backend, QA]*.

### Даты

Поля дат (системные `Срок`, `Создано`, `Обновлено`, кастомные `Date Picker`/`Date Time Picker`) показывают **выбор даты** (`yyyy-MM-dd`).

- Значение поля на задаче сравнивается в формате `yyyy-MM-dd`.
- Для точного совпадения используйте **равно** и укажите дату.
- Для частичного совпадения (например, по месяцу) уместнее текстовый сценарий; в датовом инпуте выбирайте конкретную дату.
- Для «заполнено/не заполнено» используйте **не пусто / пусто** без значения.

Пример: *Срок **не пусто*** — правило сработает, если у задачи задан срок.

### Типы задач, приоритеты, статусы, резолюции

Предопределённые системные поля: **Тип задачи** (`issuetype`), **Приоритет**, **Статус**, **Резолюция** — показывают соответствующий список значений (мультиселект с поиском).

Пример: *Тип задачи **равно** [Ошибка, Задача]*.

### Компоненты и версии

**Компоненты**, **Версии (Fix Versions/Affected Versions)** — значения берутся из текущего проекта и показываются мультиселектом.

Пример: *Компоненты **содержит** [Backend]*.

### Текстовые поля

Поля без предопределённого набора (`Summary`, `Description`, кастомные текстовые поля) — обычное текстовое поле. Для частичного совпадения используйте **содержит**.

Пример: *Summary **содержит** [срочно]*.

## Примеры правил

1. **Назначение по компоненту**
   - Цель: Исполнитель = Иван Иванов.
   - Условие: Компоненты **содержит** `Backend`.

2. **Наблюдатели по типу задачи**
   - Цель: Наблюдатели = [Петров, Сидоров].
   - Условие: Тип задачи **равно** `Ошибка`.

3. **Соисполнители по опции**
   - Цель: Соисполнители = [QA-команда].
   - Условие: Кастомное поле «Команда» **равно** `QA`.

4. **Исполнитель + наблюдатели одним правилом**
   - Цель: Исполнитель = Иванов, Наблюдатели = [Петров].
   - Условие: Приоритет **равно** `Highest`.

5. **Всегда назначать**
   - Цель: Исполнитель = дежурный.
   - Условий нет (применяется всегда).

## Технические детали

- Правила хранятся в Active Objects (`AO_AUTOASSIGN_RULE`), привязка — по ключу проекта.
- Условия хранятся как JSON (список `{fieldId, operator, values}`).
- Слушатель — событие `ISSUE_CREATED`.
- Обновление полей задачи выполняется через `IssueManager` / `CustomField.setCustomFieldValue`; наблюдатели добавляются через `WatcherManager.startWatching`.
- REST API: `/rest/autoassignment/1.0/...` (`config`, `fields`, `fields/{id}/values`, `users`, `rules`).
